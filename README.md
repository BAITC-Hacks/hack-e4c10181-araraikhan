# Аким на 5 часов

Симулятор решений по пяти районам Астаны для HackAlem AI. Пользователь выбирает ровно пять инициатив в пределах бюджета 100. Программа рассчитывает последствия на горизонте восьми кварталов, а OpenAI объясняет проверенные результаты.

## Быстрый запуск

Нужен Node.js 22 или новее. Внешних зависимостей нет.

```sh
cd simulator
node --env-file-if-exists=.env server.mjs
```

Открыть http://localhost:5173. Без ключа работают расчёты, проверка ограничений, пример, визуализация и автоматический разбор по правилам.

## Подключение AI

Скопируйте `simulator/.env.example` в `simulator/.env`, укажите свой `OPENAI_API_KEY` и при необходимости доступную вашему проекту модель в `OPENAI_MODEL`. Перезапустите сервер. Ключ хранится только на сервере; `.env` исключён из Git. Не вводите ключ в интерфейс и не отправляйте его в чат.

Для опубликованной версии задайте `OPENAI_API_KEY` как серверный секрет в Sites, `OPENAI_MODEL` — как переменную окружения. Локальный `.env` не переносится в опубликованный сайт. Пока секрет не установлен, AI-кнопка отключена и режим явно подписан «Автоматический разбор по правилам».

AI использует [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text), `store: false`, серверный пересчёт и ограниченный набор фактов. Ответ модели может содержать ошибку: авторитетными остаются числа интерфейса. Живой запрос к OpenAI требует действительного ключа и доступного баланса; он не входит в автономные тесты.

## Сценарий демонстрации

1. Нажмите «Попробовать пример».
2. Убедитесь: M7, M8, M10 в Нуре; M12 по городу; M5 в Сарыарке. Стоимость 95, остаток 5.
3. Итоговый Score: **56.54307**, исходный: **52.55768**, разница: **3.98539**.
4. S1 Нуры: 38 → 48; S2: 35 → 43.75. Оба критических значения устранены.
5. Нажмите «Разобрать сценарий», посмотрите формулу, компромиссы и допустимые замены одной меры.
6. При подключённом ключе нажмите «Получить объяснение AI».
7. Удалите меру: итоговый Score больше не рассчитывается до пятого допустимого решения.

## Источник и правила

Два исходных Word-документа находятся в `instructions/`. Данные синтетические, не являются реальными прогнозами. 5 районов, 10 показателей, 14 инициатив. Все показатели направлены одинаково: 0 — плохо, 100 — хорошо.

- Бюджет: 100, ровно 5 разных мер, не более 2 из одного направления.
- Районная мера требует один район, городская не имеет района и применяется ко всем пяти.
- M1 и M3 несовместимы глобально; M4/M7 и M5/M13 несовместимы в одном районе.
- Реализованный эффект каждой меры: `полный эффект × (8 − лаг) / 8`.
- Синергии M1/M2, M10/M12, M5/M6 добавляют 2 балла соответствующему показателю в районе первой меры, без уменьшения по лагу.
- После сложения эффектов и синергий значения ограничиваются диапазоном 0–100.
- Оценка района: сумма показателей с весами `0.10, 0.10, 0.09, 0.11, 0.11, 0.11, 0.09, 0.09, 0.10, 0.10`.
- Средняя по городу: оценки районов × доли населения `0.27, 0.24, 0.20, 0.13, 0.16`.
- `Score = 0.7 × средняя + 0.3 × минимум − число ячеек строго ниже 40`.
- Промежуточные вычисления не округляются. Округление применяется только к отображению.
- До пяти решений интерфейс показывает предварительные показатели и исходный Score, но не выдаёт окончательную оценку незавершённого сценария.

**Неоднозначность брифа:** краткий документ упоминает пять направлений. Подробный датасет допускает максимум две меры на направление, то есть 3–5 направлений. Реализованы подробные правила, которым соответствует пример организаторов. Перед защитой стоит подтвердить эту трактовку.

## Устройство проекта

- `simulator/public/engine.mjs` — данные, валидатор, детерминированные расчёты и поиск лучших допустимых замен одной меры.
- `simulator/public/app.mjs` — интерфейс, состояние, предварительные изменения и AI-запрос.
- `simulator/public/index.html`, `style.css` — адаптивный интерфейс на русском.
- `simulator/api.mjs` — проверяет сценарий повторно на сервере, считает результаты и передаёт только проверенные факты OpenAI. Клиентские Score игнорируются.
- `simulator/server.mjs` — локальный сервер; публикует только явно разрешённые файлы.
- `simulator/build.mjs` — собирает автономный Cloudflare Worker без внешних зависимостей.
- `simulator/tests/` — воспроизведение эталона, ограничения, лаги, синергии, клиппинг, порог 40, порядок решений и AI API с подставным провайдером.

Все изменения хранятся в текущем сценарии браузера до перезагрузки страницы. Аккаунты, сохранение сценариев и рейтинг команд в MVP не добавлены. Подсказки перебирают одну замену, а не ищут глобальный оптимум. До публичного многопользовательского запуска AI-эндпоинту потребуется пользовательская авторизация и устойчивые лимиты запросов. Новая версия Sites предназначена для приватного доступа владельца.

## Проверка и сборка

```sh
cd simulator
node --test tests/*.test.mjs
node build.mjs
```

Результат сборки: `simulator/dist/server/index.js`, модуль Worker с `default.fetch`. В сборку не попадает `.env`. Доступны `GET /api/config` и `POST /api/analyze`.

При поддержке WebMCP браузером доступны `read_city_scenario` и `set_city_scenario`. Они используют то же состояние и тот же валидатор, что интерфейс. Поддержка браузерами необязательна.
